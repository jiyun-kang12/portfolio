AI 기반 실시간 학습 집중도 평가 플랫폼
온라인 강의 · 에듀테크 서비스 기획 · 3-역할 시스템 설계 · 지표 체계 수립
온라인 강의에서 강의자는 학습자의 반응을 실시간으로 확인할 수 없다는 구조적 한계가 있습니다. 별도 앱 설치 없이 웹캠 하나로 비침습적 집중도 측정이 가능하다는 핵심 인사이트에서 서비스 컨셉을 도출했습니다.
문제 정의 — 온라인 강의의 구조적 공백
  • 오프라인 강의: 강의자가 표정·고개·태도로 이해도·집중도를 즉각 파악 가능
  • 온라인 강의: 카메라를 꺼두는 경우 많음 → 강의자에게 피드백 채널 전무
  • → "강의 중 개입 시점을 모른다"는 강의자 Pain Point를 핵심 문제로 설정
  • 세션 종료 후에도 강의 개선을 위한 데이터 기반 피드백 없음
  • → 세션 데이터 누적 기반 강의 개선 리포트를 부가 가치로 기획
3-역할 시스템 설계 — 학습자·강의자·매니저
  • 학습자: 웹캠 허용 + 세션 참여 (최소한의 부담, 동의 기반 설계)
  • 강의자: 실시간 집중도 대시보드 + 즉각 개입 알림 수신
  • 매니저: 강의자/학습자 계정 관리 · 강의 세션 통계 모니터링
서비스 전체 흐름 — 학습자 웹캠 → AI 분석 → 강의자 대시보드 → 리포트
지표 설계 철학 — 집중도·피로도를 분리한 이유
  • 단순 "집중/산만" 이분법은 현장 개입 근거로 부족 → 다차원 지표 설계 필요
  • 집중도: 현재 수업에 얼마나 능동적으로 참여하고 있는가 (즉각 개입 판단)
  • 피로도: 누적 스트레스·졸음 수준 (강의 페이스·휴식 조절 판단)
  • → "집중하지만 피로한 상태"를 분리하여 강의자가 과부하 학습자를 식별 가능
  • 신호 5종(표정·시선·자세·핸드폰·눈깜빡임)을 가중치 합산 → 단일 스코어로 압축

강의자 대시보드 UX 기획 — 정보 구조 & 인지 부하 최소화

  • 집중·산만·졸음·핸드폰 4종 카테고리 필터 → 개입이 필요한 학습자를 1초 내 식별
  • → "전체를 다 볼 필요 없이 문제 상황만 빠르게 파악" 시나리오 중심 설계
  • 집중도 수치보다 상태 레이블(아이콘+색상 코딩) 우선 표시 → 강의 중 인지 부하 고려
  • 실시간 라인차트: 수업 흐름에서 집중도가 꺾이는 지점을 강의자가 인식 가능
알림 설계 — 쿨다운·임계값 기반 과알림 방지
  • 핸드폰 감지 알림: 30초 쿨다운 (반복 탐지 시 강의자 집중 방해 방지)
  • 졸음 감지 알림: 1분 쿨다운 (학습자 EAR 임계값 지속 위반 시만 발화)
  • → "필요한 알림만" 원칙 — 알림 피로도(alert fatigue)를 서비스 기획 단계에서 설계에 반영
강의자 실시간 모니터링 대시보드 — 학습자별 집중도 카드 + 카테고리 필터
세션 리포트 기획 — LLM 활용 결정의 배경
  • 수치 그래프(집중도 추이·표정 분포)는 제공되지만 강의자가 해석에 전문성 필요
  • → 자연어 요약 리포트로 "이 시간대에 집중도가 떨어진 이유"를 직관적으로 제공
  • Gemini LLM: 세션 집계 데이터를 구조화된 프롬프트로 전달 → 강의 방식 개선 제안 자동 생성
  • 리포트 수신자 = 강의자 (비전문가) → 기술 용어 없는 평어 출력 요건 설계
핵심 기획 판단
집중도 데이터 단독으로는 "무엇을 바꿔야 하는지" 강의자가 모름 → AI 해석 레이어를 리포트에 결합하여 데이터-인사이트 간 갭을 없앰

  • → 브랜드 디자인 철학을 AI에 학습시켜 수정 없이 바로 활용 가능한 프로토타입 생성

  • 현대차 공식 이미지 1,988장 + 디자인 철학 문서 + VoC + 트렌드 리포트 통합

  • → 단순 이미지 데이터가 아닌 "브랜드 스토리"가 담긴 멀티모달 데이터셋 설계
서비스 전체 파이프라인 — Text → Image → 3D → 4D 통합 워크플로우

저작권 정보 챗봇 for 콘텐츠 크리에이터
플랫폼별 저작권 정책 통합 · 3단계 라우팅 설계 · 신뢰도 우선 평가 체계
YouTube·Instagram·네이버 블로그 등 플랫폼마다 저작권 정책이 다르고, 크리에이터들은 이를 파편화된 채로 각자 검색해야 합니다. 플랫폼·법령·상황별로 정확하고 근거 있는 답변을 제공하는 단일 챗봇을 기획했습니다.
커버리지 전략 — 무엇을 포함할지 결정 과정
  • 타겟: 플랫폼 정책 → YouTube·Instagram·네이버 블로그 (크리에이터 3대 채널)
  • 법령: 국내 저작권법 + 공정 이용(Fair Use) 원칙 (국내 활동 크리에이터 니즈 반영)
  • 제외 범위: 법적 조언 대신 "정보 제공"으로 서비스 포지셔닝 → 책임 범위 명확화
  • → 어디서나 쓸 수 있는 범용 챗봇이 아닌, 크리에이터 워크플로우에 맞춘 특화 서비스
데이터 구축 전략 — 정부 PDF + 플랫폼 정책 크롤링
  • 정부 저작권 PDF 자동 파싱 + 플랫폼 FAQ 크롤링으로 공식 출처 기반 지식베이스 구성
  • → 비공식 해석이 아닌 1차 출처 문서 기반으로 신뢰도 확보
응답 파이프라인 진화 — 단순 검색에서 3단계 라우팅으로 단계적 개선
3단계 라우팅 기획 — 질문 유형별 최적 응답 경로
  • RAG 경로: "YouTube 쇼츠에 타인 음악 사용 가능한가?" → 문서 검색 기반 답변
  • Tool Call 경로: 최신 정책 변경 확인 등 실시간 조회 필요 시
  • LLM 직접 응답: 저작권 개념 설명 등 일반 지식 질문 시
  • → 모든 질문에 무조건 RAG를 거치지 않음 → 불필요한 검색 비용·지연 제거
평가 지표 우선순위 설계 — Faithfulness 최우선
저작권 정보는 잘못된 답변이 실질적 법적 피해로 이어질 수 있음 → Relevancy보다 Faithfulness(답변의 문서 근거 충실도)를 최우선 지표로 설정

Project 06MOOC 온라인 학습 이탈률 예측 — 데이터 기반 문제 정의
2025.05 · 1개월 · 팀 4명
Toy Project
MOOC 온라인 학습 이탈률 예측
도메인 기반 타겟 변수 정의 · Recall 우선 평가 설계 · 파생 변수 철학
MOOC 플랫폼의 만성적인 고이탈률(85~90%) 문제를 단순 기술 문제가 아닌 교육 도메인 관점의 문제로 재정의하는 데서 기획을 시작했습니다.
타겟 변수 정의 — "이탈"을 어떻게 볼 것인가
  • 데이터상 결과값: Withdrawn(중도 탈락) / Fail / Pass / Distinction
  • 단순 Withdrawn만 이탈로 정의 시: 학습 목표 미달성자를 성공으로 오분류
  • → Fail 결과를 이탈(1)로 포함: 과정을 이수했더라도 목표를 달성하지 못한 경우도 이탈
  • 비즈니스 임팩트: MOOC 플랫폼 수익은 수료·자격증 취득 연계 → Fail 학습자 방치는 플랫폼 손실
파생 변수 설계 — 행동 패턴 수치화 철학
  • sum_click: 총 학습 활동량 → "얼마나 많이 접속했는가"
  • avg_score: 평균 점수 → "학습 성취도 추이"
  • last_click_week: 마지막 활동 주차 → "언제 이탈했는가 (조기 이탈 감지)"
  • → 원시 로그 데이터가 아닌 행동 의미를 담은 파생 변수로 모델 해석 가능성 확보
코드 프레젠테이션별 이탈률 — 데이터 기반 문제 심각성 확인
평가 지표 설계 — Recall 최우선의 비즈니스 근거
  • FN(이탈인데 정상 예측): 조기 개입 기회 놓침 → 실제 이탈로 이어짐 = 큰 손실
  • FP(정상인데 이탈 예측): 불필요한 개입 리소스 낭비 = 작은 손실
  • → "놓치지 않는 것이 잘못 개입하는 것보다 중요" → Recall 최우선 최적화 결정
  • 임계값(threshold) 하향 조정으로 Recall을 높이는 방향으로 모델 튜닝
