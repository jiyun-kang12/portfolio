📌 프로젝트 목표

제 1회 서울 플레이업 AI 게임 챌린지 출품작으로, 서울역·청계천 등 실제 서울 공간에 남아 있는 과거의 흔적을 탐색하며 사라진 장소와 잊혀진 사람들의 기억을 복원하는 3D 스토리 기반 퀘스트 탐험 게임입니다. 도시 공간을 단순 배경이 아닌, 역사적 사건과 평범한 사람들의 삶이 쌓인 서사적 무대로 재현하는 것을 기획 의도로 삼았습니다.

2인 팀 "서울을 빚다"로 참가하여 약 6주간 개발했습니다.

📌 기획 의도

서울의 많은 장소들은 개발과 변화 속에서 모습이 바뀌었지만, 그곳을 지나간 사람들의 삶과 기억은 완전히 사라지지 않았습니다.

《서울의 유령 노선》은 현재의 서울을 걷는 플레이어가 평소에는 지나치기 쉬운 단서들을 발견하고, 그 단서를 통해 장소 안에 남아 있는 역사와 사람들의 이야기를 복원하도록 설계된 게임입니다. 이 게임에서 다루는 기억은 거대한 사건만이 아니라, 역사 속에서 이름을 잃거나 가난 속에서 하루를 버텨야 했던 평범한 사람들의 기억입니다.

서울은 단순한 도시 공간이 아니라, 수많은 사람들의 삶과 기억이 쌓여 만들어진 장소입니다.

📌 주요 장소 및 퀘스트

각 장소는 현재의 공간에 남아 있는 과거의 기억을 중심으로 구성됩니다. 플레이어는 장소별 NPC의 기억을 복원하는 퀘스트를 수행하며, 서울이라는 도시가 어떤 사람들의 삶과 기억 위에 세워졌는지를 체험하게 됩니다.

① 서울역 편

장소 소개

서울역은 많은 사람들이 서울에 처음 도착하거나 떠났던 공간입니다. 현재의 서울역과 구서울역이 공존하는 이곳에는 과거 서울로 올라온 사람들의 기대, 불안, 상실의 흔적이 남아 있습니다. 본 퀘스트에서 서울역은 일제강점기의 역사적 배경과 연결되며, 당시 많은 사람들이 창씨개명으로 인해 본래의 한국 이름 대신 일본식 이름을 사용해야 했던 사실을 다룹니다.

메인 퀘스트: 잃어버린 이름표

서울역에서 만나는 NPC는 서울에 기대를 품고 올라온 상경 노동자입니다. 그는 경성역에 도착했지만, 끝내 자신의 본래 이름으로 불리지 못한 인물입니다.

그는 경성역에 도착했지만, 끝내 자신의 이름으로 불리지 못했습니다.
서울역에 숨겨진 단서들을 찾아 그가 잃어버린 이름과 기억을 되찾도록 도와주어야 합니다.
단서 안내
단서의미
낡은 이름표일본식 이름으로 불려야 했던 현실을 보여주는 단서
찢어진 편지 조각가족이 불러주던 본래 이름의 흔적을 담고 있는 단서

퀘스트 의도

서울역 퀘스트는 일제강점기 창씨개명이라는 역사적 배경을 직접 설명하는 데 그치지 않고, 이름을 빼앗긴 한 개인의 기억을 따라가도록 구성되어 있습니다. 이를 통해 플레이어는 서울역이라는 공간을 단순한 교통시설이 아니라, 누군가의 삶이 시작되고 흔들렸던 장소로 다시 바라보게 됩니다.

② 청계천 편

장소 소개

청계천은 현재 시민들이 산책하고 머무는 공간이지만, 과거에는 다양한 상인과 사람들의 생활이 이어지던 장소였습니다. 청계천 다리인 모전교의 모전(毛廛)은 과일을 팔던 가게라는 뜻으로, 주변에 과일 가게들이 많았던 상업 공간의 흔적이 다리 이름에도 남아 있습니다. 본 퀘스트는 과일 가게 상인의 기억을 중심으로 구성되지만, 동시에 그 주변에서 가난과 굶주림을 겪던 아이의 이야기를 함께 담고 있습니다.

메인 퀘스트: 모전교, 잊혀진 상인의 기억

청계천에서 만나는 NPC는 모전교 근처에서 과일을 팔던 상인입니다. 그는 자신이 물건을 팔았다는 사실은 기억하지만, 무엇을 팔았는지는 기억하지 못합니다.

그는 청계천 곁에서 장사를 했지만, 끝내 자신이 무엇을 팔았는지 기억하지 못했습니다.
청계천 모전교 주변에 숨겨진 단서들을 찾아 그가 잊어버린 기억을 찾도록 도와주어야 합니다.
단서 안내
단서의미
먼지 쌓인 모전교 교명석다리 이름의 유래를 통해 이곳이 과일 가게와 관련된 장소였음을 알려주는 단서
과일 바구니와 숨겨진 쪽지상인이 팔던 물건이 과일이었으며, 그 과일이 누군가를 위해 남겨진 것이었음을 보여주는 단서
녹슨 손저울과일을 달아 팔던 상인의 장사 기억을 확인하게 하는 단서

청계천 퀘스트는 모전교 주변의 과일 가게라는 장소적 배경을 바탕으로, 그 안에 존재했던 가난한 아이들의 삶을 함께 보여줍니다. 이 이야기는 청계천을 단순한 산책로나 관광 공간이 아니라, 누군가의 생계와 굶주림, 그리고 작은 연민이 함께 남아 있던 장소로 다시 바라보게 합니다.

문제 1. URP 전환 이후 수면 셰이더 오작동

상황
청계천 씬 작업 중, 기존 WaterFlowController가 레거시 파이프라인의 _MainTex/_BumpMap 속성을 직접 참조하고 있어 URP/Lit 머티리얼에서 수면 흐름 애니메이션이 정상적으로 반영되지 않음.

// HasProperty 체크로 _BaseMap 우선 사용, 미지원 시 _MainTex로 폴백
string texProperty = mat.HasProperty("_BaseMap") ? "_BaseMap" : "_MainTex";

// 런타임에 공유 머티리얼이 아닌 인스턴스 머티리얼 사용 (다른 오브젝트 영향 차단)
Material instanceMat = renderer.material;

// 오프셋 값을 매 프레임 1로 모듈러 연산 → 장시간 플레이 시 float 정밀도 손실 방지
offset.x = (offset.x + flowSpeed * Time.deltaTime) % 1f;
instanceMat.SetTextureOffset(texProperty, offset);
해결
HasProperty 체크로 _BaseMap 우선 사용, 미지원 시 _MainTex로 폴백하도록 속성 해석 로직 재설계. 런타임에 공유 머티리얼이 아닌 인스턴스 머티리얼을 사용하도록 변경해 다른 오브젝트에 영향 없도록 격리. 오프셋 값을 매 프레임 1로 모듈러 연산해 장시간 플레이 시 float 정밀도 손실 방지. → URP 환경에서 수면 흐름 효과 정상 작동, 장시간 세션에서도 안정적으로 유지.

문제 2. 플레이어 이동 스크립트의 NullReferenceException 위험

상황
PlayerMovement.cs가 CharacterController가 없거나 런타임 중 파괴된 경우를 가정하지 않아, 접근 시 크래시 위험 존재.

void Start()
{
    controller = GetComponent<CharacterController>();
    if (controller == null)
    {
        Debug.LogError("CharacterController가 없습니다. PlayerMovement를 비활성화합니다.");
        enabled = false;
        return;
    }
}

void Update()
{
    if (controller == null) return;
    // 이동 로직
}
해결
Start()에서 컴포넌트 부재 시 에러 로그를 남기고 스크립트를 비활성화. Update()에서도 매 프레임 null 체크를 추가해 안전하게 조기 반환. → 씬 구성 실수나 런타임 중 컴포넌트 제거로 인한 크래시를 사전에 방지.
