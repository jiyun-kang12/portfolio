Real-Time Learner Monitoring & Dashboard System
5-channel live data collection · Multi-role dashboard · WebSocket streaming · Session reporting
Designed and built an end-to-end data monitoring system that collects 5 simultaneous behavioral signals from learners in real time and streams them to an instructor dashboard at 0.1-second intervals — bridging the data gap that makes online instruction hard to adjust on the fly.
Data Collection Layer — 5 Concurrent Signal Channels
  • Facial expression: RandomForest on 52 MediaPipe blendshapes → 5-class emotion label
  • Gaze direction: Iris landmark-based eye-tracking via FaceLandmarker (horizontal · vertical)
  • Head posture: 4×4 rotation matrix → yaw / pitch deviation from neutral
  • Blink / drowsiness: Eye Aspect Ratio (EAR) computed per frame
  • Phone usage: YOLOv11s object detection on webcam frames sent to GPU server
  • → All 5 channels merged server-side into a unified per-learner data record every 100 ms

Project 01KPI Definition · Live Dashboard Design · Automated Session Report — 2/2
KPI Design — Defining "Concentration" and "Fatigue" as Measurable Scores
  • Concentration score: focus = gaze × 0.60 + head × 0.40 − shoulder × 0.10
  • EMA smoothing (α = 0.05) + 20–25 frame state confirmation to suppress signal noise
  • Fatigue score: fatigue = EAR × 0.25 + elapsed time × 0.35 + gaze fixation × 0.25 + head movement × 0.15
  • Separates "focused but fatigued" from simple distraction — enables nuanced instructor action
  • Two independent KPIs let instructors distinguish who needs a break vs. who is disengaged
Instructor Dashboard — Live Data Visualization
  • Per-learner status cards: color-coded state labels (Focused / Distracted / Drowsy / Phone) for instant scan
  • Category filter: surface only learners who need intervention — minimizes cognitive load during class
  • Real-time line chart: concentration trend across the session timeline (Recharts)
Live instructor dashboard — per-learner concentration cards + category filter
Alert Thresholds & Automated Session Report
  • Phone detection alert: 30-second cooldown — fires only on confirmed YOLOv11s detection
  • Drowsiness alert: 1-minute cooldown — triggers when EAR falls below threshold for sustained frames
  • Session-end report: PostgreSQL aggregates → Gemini LLM generates natural-language improvement summary
  • Report includes: concentration trend chart · emotion distribution radar · LLM-written teaching recommendations
  • → Raw session data is automatically transformed into an actionable report without manual analysis

Project 06MOOC Learner Dropout Prediction — Data Analysis & Metric Design
May 2025 · 1 month · Team of 4
Data Analysis
MOOC Dropout Prediction — EDA to Production Model
4-table data integration · Feature engineering · Recall-first evaluation · XGBoost optimization
Addressed the chronic 85–90% dropout problem in MOOC platforms through a machine learning pipeline built on the OULAD dataset. The project required domain-driven data definition, multi-table integration, feature engineering, and business-aligned metric selection — core data coordination competencies.
Data Integration — 4-Table Merge & Target Variable Definition
  • Merged 4 OULAD tables: StudentInfo · StudentRegistration · StudentAssessment · StudentVle
  • Target variable: Withdrawn + Fail → labeled as dropout (1)
  • Rationale: a learner who completes a course but fails to meet learning goals also represents platform churn — aligned with business impact, not just technical completion status
Feature Engineering — Translating Raw Logs into Behavioral Signals
  • sum_click: total engagement volume — "how much did the learner interact?"
  • avg_score: assessment performance trend — "how is achievement progressing?"
  • last_click_week: recency of last activity — "when did disengagement begin?"
  • → Raw event logs transformed into interpretable behavioral features for both model input and stakeholder reporting
Dropout rate by course presentation — EDA reveals semester-1 attrition patterns
Evaluation Metric Design — Recall-First Based on Business Cost Analysis
  • False Negative (missed dropout): learner gets no intervention → actual churn = high cost
  • False Positive (unnecessary outreach): wasted resource, minor inconvenience = low cost
  • → Prioritizing Recall over Accuracy: a deliberate data-driven decision grounded in business impact, not model performance alone
  • XGBoost final model: threshold tuned downward to maximize Recall; 7 models benchmarked before selection

Pipeline evolution — simple retriever → 3-stage intent-routed RAG
